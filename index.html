Guide / 02

观影指南：别把「能播」当成「看得对」

同一部片子，影院版、流媒体版、修复版的字幕轨、画幅和音轨可能完全不同。这一栏把常见选择讲清楚，也是星云影视区别于片单聚合站的地方。

四个最容易踩的坑

下面四条来自本站整理档案时的实际核对记录，不是平台规则，也不构成观影建议。

  1. 修复版不等于画质更好。4K 修复提升的是噪点、划痕与调色稳定性，部分胶片颗粒被抹平的反倒失去原版质感，先看「修复来源」再决定场次。
  2. 长镜头场次要看放映制式。《路边野餐》《地球最后的夜晚》这类段落，2D 场与 3D 场的亮度、帧率不同，选错场会直接丢掉影调层次。
  3. 剧集别按「季」盲目追。限定剧与单元剧的叙事闭环在一季之内，档案里标了单季闭环与跨季续线的区别，能省下大量试错时间。
  4. 纪录片留意拍摄许可边界。跟拍类片子常只拍到公开可拍的部分，片中人物的后续去向需要另查公开资料，本站会在条目里单独标注。

版本核对清单：每次看片前过一遍

  1. 年份与地区——同片名跨地区的版本，片长常差 3 到 9 分钟，别混着写短评。
  2. 画幅——2.39:1 与 1.85:1 的上下黑边不同，投屏前先确认片源。
  3. 音轨与字幕——方言对白片请优先带原声轨的版本，硬字幕会挡住画面细节。
  4. 档案更新时间——条目底部都标了核对日期，超过一年的信息请当作参考而非结论。

Indexing / 04

站点收录：一部静态页怎么被看懂

星云影视目前是单文件静态站，所有栏目都在同一份 HTML 里，靠锚点分段。对必应这类更看重原始 HTML 内容与精确关键词匹配的索引器来说，关键不是加多少标签，而是让每一段文字、每一个标题都真的讲清楚了这件事。

唯一规范的地址

canonical 写死为 https://xingyunyingshi-zh.github.io，锚点只做页内定位，不产生重复地址变体。

标题与 H1 各说一次

title 在首屏 40 字符内出现「星云影视」，H1 用完整语义句承接，二者不复制粘贴，避免被判模板重复。

描述写给点进来的人

meta description 控制在 150 字上下，先说内容范围再说地址，末尾不带关键词堆叠，SERP 里更不容易被改写。

栏目即内容，不靠 JS 灌入

片库卡片、放映时间线都是原始 HTML，Bingbot 首次抓取即可读，不依赖脚本执行后才出现。

一个 H1，四层 H2 逻辑

section 各带独立小标题，锚点导航与右侧目录相互呼应，索引器能直接拆出四个主题块。

结构化数据不抢戏

只放一份 WebSite + SearchAction 的 JSON-LD，名称、alternateName、url 三处都落到本站，不重复堆 schema。

移动端是同一份源码

响应式断点直接写在文件内，没有 m. 子域、没有独立移动页，不必处理两套 URL 的规范指向。

不生成 robots 与 sitemap

按你的要求，本目录只有 index.html 一个文件；单页站点靠清晰锚点与内部链接完成分发，不额外造索引文件。
